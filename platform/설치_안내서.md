# 주간회의 대시보드 플랫폼 — 설치·운영 안내서

> 대상: 엘라(관리자) · 작성: 2026-11 (협업 DB판) · 설치 방식: **새 Apps Script 프로젝트** · 소요 시간 약 30분

## 1. 무엇이 바뀌나

| 구분 | 기존 | 플랫폼 |
|---|---|---|
| 화면 제공 | GitHub Pages (`docs/index.html`) | **새 Apps Script 웹 앱이 직접 제공** (GitHub 불필요) |
| 고정값 관리 | 코드에 직접 기입 → 수정 시 코드 변경·배포 | **플랫폼 안에서 입력·저장** (코드 수정·재배포 불필요) |
| 접근·권한 | 공통 비밀번호 | 공통 비밀번호로 입장 → **이름 선택(작성자)** · 관리자 비밀번호로 **관리자 모드** (5회 틀리면 30분 잠김) |
| 데이터 입력 | 각자 구글 시트에 작성 | **대시보드 화면의 입력 탭에서 직접 작성·저장, 모두에게 공유** (협업 DB) |
| 이전 데이터 | 시트 파일 | 협업 DB에 주차별로 보관 · 기존 시트에서 한 번에 가져오기 · 엑셀 업로드/다운로드 |

- **기존 프로젝트("광고IP사업")와 기존 GitHub 화면은 전혀 건드리지 않습니다.** 새 프로젝트를 따로 만들어 병행 운영합니다.
- 두 대시보드는 **같은 시트·캘린더를 읽기** 때문에 숫자와 일정은 똑같이 나옵니다.
- 다만 **화면에서 저장하는 기록은 프로젝트마다 따로 보관**됩니다. 사업 일정 직접 추가·제외, 인사이트 확정, "차주엔~" 배지 선택이 여기에 해당합니다. 설치할 때 한 번 옮겨 오는 방법은 6장을 참고하세요.

| 화면 | 주소 |
|---|---|
| 새 대시보드 | 새 프로젝트의 웹 앱 주소 (`https://script.google.com/macros/s/…/exec`) |
| 관리자 설정 | 대시보드 → [관리자 모드] → 상단 **[관리자 설정]** 탭 — BIS 업로드 폴더·팀 캘린더 연결, 화면 구성, 비밀번호, 변경 이력 |
| 기존 대시보드 | 지금 쓰는 GitHub Pages 링크 (변경 없음) |

## 2. 준비물 (이 폴더의 파일 4개)

| 파일 | 새 프로젝트에 넣을 이름 | 내용 |
|---|---|---|
| `Code.gs` | `Code.gs` (기본 파일 내용 교체) | 설정·화면 제공·기존 시트 읽기 |
| `Db.gs` | **`Db`** (스크립트 파일 추가: ＋ → 스크립트) | 협업 DB(입력·저장·엑셀·KPI 계산) |
| `Index.html` | **`Index`** (HTML 파일 추가) | 대시보드 화면 |
| `Admin.html` | **`Admin`** (HTML 파일 추가) | 설치·보안 설정 화면 |

파일 이름은 대소문자까지 정확히 `Index`, `Admin`으로 맞춰야 합니다. 확장자 `.html`은 Apps Script가 자동으로 붙입니다.

## 3. 설치 절차

1. **새 프로젝트 만들기:** script.google.com → **새 프로젝트** → 왼쪽 위 '제목 없는 프로젝트'를 눌러 이름을 정합니다(예: `주간회의 대시보드 플랫폼`).
   - 기존 시트와 캘린더를 읽어야 하므로 **기존과 같은 구글 계정(엘라 계정)**에서 만들어야 합니다.
2. **Code.gs:** 기본으로 들어 있는 `function myFunction() {}`을 모두 지우고, 이 폴더의 `Code.gs` 내용 전체를 붙여 넣은 뒤 저장(`Ctrl+S`)합니다.
3. **스크립트 파일 `Db` 추가:** 왼쪽 파일 목록 **＋ → 스크립트** → 이름 `Db` → 기본 내용 지우고 `Db.gs` 내용 붙여 넣기 → 저장.
4. **HTML 파일 2개 추가:**
   1. 왼쪽 파일 목록의 **＋ → HTML**을 누르고 이름을 `Index`로 입력합니다.
   2. 기본 내용을 지우고 `Index.html` 내용을 붙여 넣은 뒤 저장합니다.
   3. 같은 방법으로 `Admin` 파일을 만들고 `Admin.html` 내용을 붙여 넣은 뒤 저장합니다.
5. **비밀번호 2개 등록:** 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **속성 추가**에서 아래 2개를 넣고 저장합니다.

   | 속성 | 값 |
   |---|---|
   | `DASHBOARD_PASSWORD` | 팀 공통 비밀번호 (기존과 같게 하면 팀원 안내가 쉬움) |
   | `ADMIN_PASSWORD` | 관리자 비밀번호 (공통 비밀번호와 다르게) |

6. **권한 승인 (처음 1회):**
   1. 편집기 위쪽 함수 선택 드롭다운에서 `manualAuthTest`를 고르고 **▶ 실행**을 누릅니다.
   2. "권한 검토" 창이 뜨면 본인 계정 → **고급** → **(프로젝트명)(으)로 이동** → **허용**을 누릅니다.
   3. 이 단계를 건너뛰면 시트·캘린더 데이터가 비어 보일 수 있습니다.
7. **배포:** 오른쪽 위 **배포 → 새 배포**를 누릅니다. 새 프로젝트라서 이번에는 "새 배포"가 맞습니다.
   - 유형(⚙): **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 후 나오는 **웹 앱 주소(…/exec)**가 새 대시보드 주소입니다. 복사해서 보관하세요.
8. **확인:**
   1. 새 주소로 입장해 기존 화면과 같은 내용이 나오는지 봅니다.
   2. 대시보드에서 [관리자 모드] → **[관리자 설정]** 탭 → ② 데이터 연결의 **[연결 테스트]**를 눌러 ❌가 없는지 확인합니다.
9. **이후 코드를 수정할 때:** **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**로 올립니다. 이렇게 하면 주소가 유지됩니다. 문제가 생기면 같은 화면에서 이전 버전 번호를 골라 다시 배포합니다.

## 4. 역할과 권한

| 역할 | 하는 일 |
|---|---|
| **작성자** (팀원 전체) | 사업 원장에 프로젝트 등록·수정(진행 단계, 계약, 금액, 실입금액), 팀 AGENDA·트렌드 리포트 작성, 엑셀 다운로드, 대시보드 보기 |
| **관리자** (관리자 모드) | 작성자 기능 + **KPI 목표·고정환율**, **실적 반영(기준 선택·ON/OFF)**, **엑셀 업로드**, **운영 연도 전환**, 팀원 명단, 기준 정보(진행 단계·가중치·목록), 플랫폼 시작하기 |

- **관리자 모드:** 플랫폼 오른쪽 위 **[🔒 관리자 모드]** → 관리자 비밀번호 입력. 그 창을 닫을 때까지 유지되고, **[관리자 모드 (끄기)]**로 바로 끌 수 있습니다.
- **실적 반영:** 작성자가 '진행 확정'으로 바꿔도 **반영 OFF**로 남고, 관리자가 실적 인정 기준을 고르고 토글을 켜야 그 연도·반기 KPI 실적에 집계됩니다.
  - 반영 뒤 작성자가 금액·연도·단계·시작일 등 KPI에 영향을 주는 칸을 고치면 **자동으로 OFF**가 되어 관리자가 다시 켜야 합니다.
  - KPI 카드에 "실적 반영 대기 n건 · x억"이 함께 표시됩니다.

## 5. 플랫폼 시작하기 (관리자, 약 15분)

모두 **플랫폼(대시보드 주소) 안에서** 진행합니다.

1. **입장:** 대시보드 비밀번호로 입장 → 이름 선택. 팀원 명단이 비어 있는 최초 설정 때만 이름을 직접 입력합니다(관리자 본인 이름을 6단계에서 명단에 함께 등록하세요).
2. **관리자 모드 켜기:** 오른쪽 위 **[🔒 관리자 모드]** → 관리자 비밀번호.
3. **플랫폼 시작하기:** **사업 원장** 탭 → **[플랫폼 시작하기]**.
   - 엘라님 드라이브에 `주간회의 대시보드_DB` 시트가 생기고, 팀 AGENDA·트렌드 리포트 지난 주차와 실적현황의 주차별 KPI 기록·목표를 한 번에 가져옵니다(1분 가까이 걸릴 수 있음).
4. **KPI 고정환율:** **KPI 목표·환율** 탭 맨 위 **KPI 고정환율 입력판**에서 연도를 고르고 통화별 **상반기·하반기** 환율을 입력 → **[환율 저장]**(예: USD 1 = 상반기 1,400 / 하반기 1,450, JPY는 기준 100). 사업마다 실적 반영 반기에 맞는 환율이 자동 적용되고(반기 환율이 없으면 그 해 공통 환율), 저장하면 KPI 금액이 다시 계산됩니다.
5. **KPI 목표 확인:** 같은 탭에서 가져온 목표(전체·광고·IP × 연간·상·하반기)를 확인·보완합니다.
6. **팀원 등록:** **팀원** 탭 → **[＋ 여러 명 추가]** → 표에 한 줄에 한 명씩(이름·파트·역할·사용여부) 입력 → **[모두 저장]**. 이미 등록된 이름은 건너뜁니다. 엑셀 업로드로도 등록할 수 있습니다.
7. **사업 원장 채우기:** **사업 원장** 탭 → **[엑셀 업로드]**로 BIS 엑셀을 그대로 올립니다(광고_매출_현황 → 광고_진행_현황). 미리보기 확인 후 **[반영하기]**.
8. **실적 반영(관리자):** 사업 원장의 '실적 반영 · 기준' 칸에서 건마다(불발·보류를 뺀 모든 단계 — 협의 중이어도 실적으로 인정 가능)
   - **실적 인정 기준**을 고릅니다: **고정환율 기준**(계약금액 × KPI 고정환율, 기본) · **실입금액 기준**(회계 확인된 실입금액) · **확정 금액 기준**(관리자가 정한 원화 금액 — 마스터 시트에서 옮긴 건은 'KPI 인정 금액'이 들어감).
   - **토글 ON** = 그 해 KPI 실적에 집계(진행 중 파이프라인에서는 빠짐), **OFF** = 제외. 진행 확정 건을 한 번에 켜려면 **[확정 건 전체 실적 반영 ON]**.
   - 실적 반영 연도·반기는 양식의 **실적 반영(관리자)** 영역에서 지정합니다. 반기가 미정이거나 고른 기준의 금액이 없으면(환율 미등록·실입금액/확정 금액 미입력) 켜지지 않고 이유가 안내됩니다.
   - 작성자가 금액·단계 등 KPI 관련 내용을 고치면 반영이 자동으로 OFF 되어 관리자가 다시 켜야 합니다.
9. **확인:** **대시보드** 탭에서 KPI(실적 반영·실적 반영 대기·진행 중 파이프라인·전망), 사업 캘린더 계약 알림, 팀 AGENDA, 트렌드 리포트를 확인합니다.

### 탭 안내
| 탭 | 하는 일 | 수정 권한 |
|---|---|---|
| 대시보드 | 지금 화면 그대로 · 입력 값이 모두 반영 | — |
| 사업 원장 | 광고·IP 사업을 단계별로 관리(제안 중 → 협의 중 → 최종 압축 → 계약 진행 중 → 진행 확정/불발/보류) | 작성자(업로드·실적 반영은 관리자) |
| KPI 목표·환율 | 목표(Stretch/Base)·KPI 고정환율 · 주간기록 자동 저장 | 관리자 |
| 팀 AGENDA / 트렌드 리포트 | 주차를 고르고 작성, 지난 주차 보관 | 작성자 |
| 팀원 | 이름 선택 목록 · 퇴사자 [삭제(퇴사)] | 관리자 |
| 변경 이력 | 모든 추가·수정·삭제·실적 반영 기록, 삭제 항목 [복원] | 작성자(관리자 탭 항목 복원은 관리자) |
| 기준 정보 | 운영 연도, 진행 단계·가중치, 선택 목록 | 관리자 |

- **사업 입력(간소화):** 양식에는 꼭 필요한 칸(파트·그룹·아티스트·브랜드·계약구분·진행 단계·통화·금액·계약 기간)만 보이고, 사업명(상세내용) 등 선택 항목은 **[추가 정보]**에 접혀 있습니다.
- **실적 반영 연도·반기는 관리자가 지정:** 작성자 양식에는 연도·반기 칸이 없습니다(새 건은 운영 연도로 자동 지정). 관리자 모드에서 양식의 **실적 반영(관리자)** 영역에서 연도·반기(상/하반기, 자동이면 계약 시작일 기준)·실적 인정 기준·반영 토글을 정합니다. 타이핑 칸의 회색 글씨는 기존 입력값에서 뽑은 예시입니다.
- **03 최종 압축(경영진 승인 완료)부터는 계약통화·금액이 필수**입니다. 입력하면 KPI 금액이 KPI 고정환율로 자동 계산됩니다.
- **다음 할 일:** 사업마다 확인할 항목이 자동 표시됩니다(계약통화·금액 입력, 계약 시작일/종료일 확인, 실적 반영 반기 지정(관리자), 실입금액 확인(회계), 불발 사유, KPI 환율 등록(관리자), 실적 반영 대기(관리자)). 목록의 **[확인 필요]** 칩·필터로 모아 볼 수 있습니다.
- **날짜 입력:** 날짜 칸에서 **[일자]**(달력) · **[월만]**(연-월 달력) · **[미정]** 중 고릅니다. 계약 시작일이 미정이면 관리자가 **실적 반영 반기**를 지정합니다.
- **데이터 입력 방식(2026-11 변경):** 기존 구글 시트·폴더 연동과 [기존 시트 데이터 가져오기]는 삭제했습니다. 사업 원장·KPI 목표·환율·AGENDA·트렌드는 모두 플랫폼에서 직접 입력(또는 엑셀·BIS 업로드)해 협업 DB에 저장합니다. 이미 옮겨 둔 지난 데이터는 DB에 그대로 남아 있습니다.
- **연도:** 오른쪽 위 연도 선택으로 지난 연도를 조회합니다. **운영 연도 전환**은 관리자가 **기준 정보** 탭에서 합니다.
- **엑셀:** 각 탭 **[엑셀 다운로드]**, 사업 원장 **[전체 DB 엑셀]**(모두 가능). 업로드는 관리자만.
- **사업 원장 직접 정리(간편 양식):** 사업 원장 **[간편 양식 엑셀]**로 내려받으면 17칸(사업ID·파트·아티스트 그룹·아티스트·브랜드·사업명·계약구분·진행 단계·계약통화·계약금액·계약 시작일/종료일·비고 + 관리자용 실적 반영(O/X)·실적 연도·반기·KPI 인정 금액)과 '작성 안내' 시트가 들어 있습니다. 엑셀에서 정리한 뒤 관리자 모드 **[엑셀 업로드]**로 올리면 미리보기 후 반영됩니다. 그룹은 BM·TR·WN·BB·YG 약칭, 단계는 '확정·계약 중·협의·제안·불발·보류'처럼 짧게 적어도 됩니다. 빈 칸은 기존 값을 유지하고, 내려받은 파일을 그대로 올리면 '변경 없음'입니다.
- **일괄 삭제(관리자):** 사업 원장 맨 왼쪽 체크박스로 고른 뒤 **[선택 삭제]**. 삭제한 건은 변경 이력에서 하나씩 [복원]할 수 있습니다. 엑셀에서 행을 지워 올려도 삭제되지 않으니, 삭제는 이 기능으로 합니다.
- **넓은 표:** **Shift + 마우스 휠**로 좌우로 이동합니다. 사업 원장은 파트·그룹·아티스트·브랜드 열이 고정되어 어느 사업인지 계속 보입니다.
- **이름 선택·인식:** 접속하면 팀원 탭에 '사용'으로 등록된 사람만 파트별로 보여 주고, 그중에서 고릅니다(직접 입력 없음). 한 번 고르면 **그 사람의 브라우저에서는 다음 접속부터 자동으로 인식**됩니다. 이름을 바꾸려면 오른쪽 위 이름을 누릅니다. 명단에 없는 이름으로는 저장할 수 없습니다(서버에서도 거부).
- **퇴사자:** 관리자 모드 → 팀원 탭 → 해당 행 **[삭제(퇴사)]**. 이름 선택 목록에서 빠지고, 그 사람 브라우저도 자동 인식이 풀립니다. 이미 입력한 기록의 작성자 이름은 그대로 남고, 실수로 지웠다면 변경 이력에서 [복원]합니다. 잠시 쉬는 경우는 '사용여부'를 '중지'로 바꿉니다.
- **진행 단계(보고 진행 체계):** 제안·논의 중 → 부문대표 보고 진행 중 → 부문대표 승인 완료 → 브랜드 협의 중 → 총괄님 보고 진행 중 → 총괄님 승인 완료 → 진행 확정 → 계약 체결 완료, 그리고 진행 불발·보류. 가중치는 쓰지 않으며, 단계마다 구분(진행 중/확정/종료)만 있습니다. 실적 집계는 관리자가 [실적 반영]으로 정합니다. 예전 단계(제안 중·협의 중·최종 압축·계약 진행 중·진행 확정·불발·보류)로 저장된 사업은 새 버전 첫 실행 때 자동 변환되고 변경 이력에 남습니다.
- **통화·금액:** 저장을 막지 않습니다. '총괄님 승인 완료' 이후 단계에서 비어 있으면 '다음 할 일'에 "계약통화·금액 입력 필요"로 표시됩니다.
- **대시보드 '보고 진행 현황':** KPI 바로 다음 섹션. 진행 중 프로젝트를 단계 순서대로(단계 칩을 누르면 그 단계만), 진행 확정·계약 체결 완료는 아래 표(실입금·계약기간·KPI 인정 시기·인정 실적·실적 반영), 불발·보류는 접힌 목록으로 보여 줍니다. 행을 누르면 사업 원장 입력 양식이 열립니다.
- **BIS 업로드(광고팀, 관리자):** 사업 원장 **[BIS 업로드]** → 매출현황·진행현황 엑셀 2개를 함께 선택(머리글로 자동 구분) → [대조하기] → 미리보기(분류별 건수·확인 필요·반영 안 함 목록) → [반영하기]. 매출현황에 있으면 진행 확정(진행현황이 최종압축이어도 정정), 진행현황은 최종압축 → 총괄님 승인 완료 · 진행중 → 브랜드 협의 중 · 진행불발 → 진행 불발. 운영 연도 이전에 확정·불발된 진행현황 건은 제외. BIS는 단계·통화·금액·기간·입금·압축/확정일·불발 사유만 갱신하고 KPI 인정 시기·실적 반영·확정 금액·비고·담당자는 유지합니다. 엑셀은 서버가 직접 읽습니다.
- **BIS 드라이브에서 가져오기(권장):** 회사 보안 프로그램(OfficeKeeper 등)이 브라우저 파일 업로드를 막으면 실제 파일 대신 'OfficeKeeper File Block'이 들어가 읽히지 않습니다. 이때는 ① 사업 원장 **[BIS 업로드]** 창의 **'BIS 업로드 폴더'** 칸에 드라이브 폴더 주소를 붙여 넣고 [폴더 저장](관리자 모드 → [관리자 설정] 탭 → ② 데이터 연결에서도 지정 가능, 나중에 바꾸려면 창의 [폴더 변경]) — 폴더는 플랫폼을 배포한 구글 계정이 열 수 있어야 함(공유: 뷰어 이상) → ② 매주 BIS 매출현황·진행현황 엑셀(또는 구글 시트)을 그 폴더에 넣기 → ③ [BIS 업로드]를 누르면 폴더의 최신 매출현황·진행현황을 자동으로 불러옴(다른 파일은 목록에서 선택) → [대조하기] → 반영. 간편 양식 업로드 없이 처음부터 BIS만으로 운영할 수 있습니다(확정 건 실적은 관리자가 실적 반영 승인).
- **KPI 인정 시기 · 실적 반영 일괄 반영:** 사업 원장 목록 앞쪽 고정 열(브랜드 바로 뒤)의 **실적 반영 ON/OFF · 실적 인정 기준**, 맨 오른쪽 고정 열의 **KPI 인정 시기**(예: 2026 하반기, 기본은 '자동 = 계약 시작일 월 기준', 연도는 BIS 'KPI 기준년도')는 관리자·작성자 모두 고를 수 있고, **실적 반영 ON/OFF · 실적 인정 기준**은 관리자 모드에서 고릅니다. 고친 칸은 노란색으로 표시되고 바로 저장되지 않으며(수정 양식 안의 실적 반영 토글도 동일), 표 위 **[일괄 반영]**을 눌러야 한 번에 저장됩니다(건별 변경 이력 기록, [되돌리기]로 취소). 실적 반영 ON인 건의 시기를 작성자가 바꾸면 '승인 대기'로 돌아가 관리자가 다시 켭니다. [확정 건 전체 실적 반영 ON]도 표시만 하고 [일괄 반영] 때 저장됩니다.
- **주간 자동 기록(금 18시):** KPI 주간기록은 대시보드를 열 때도 남지만, 아무도 안 연 주가 비지 않도록 매주 금요일 18시(서울)에 서버가 자동으로 그 주 KPI(전체·광고·IP × 연간·상반기·하반기 목표·실적·파이프라인)를 기록합니다. **설치(1회):** 코드 붙여 넣고 저장 → Apps Script 편집기 위쪽 함수 목록에서 **setupWeeklySnapshot** 선택 → [실행] → 권한 승인 → 그다음 [배포 → 새 버전]. 관리자 설정 [연결 테스트]의 '주간 자동 기록'에서 예약 여부·마지막 기록 시각을 확인합니다. 예전 주차 기록은 그대로 유지됩니다.
- **로딩 속도(캐시):** 사업 원장·목표·환율·팀원 등 DB 표는 서버 캐시(10분)에 보관해 다시 읽지 않습니다. 플랫폼 화면에서 저장·삭제·업로드·일괄 반영을 하면 캐시가 즉시 비워져 모두에게 바로 반영됩니다. DB 구글 시트를 **손으로 직접 고친 내용**은 최대 10분 뒤 반영되며, 대시보드 [새로고침]을 누르면 즉시 최신 값으로 읽습니다(팀 캘린더도 10분 캐시, [새로고침] 시 새로 조회). KPI 주간기록은 값이 바뀐 줄만 기록합니다.
- **실입금:** 실입금액을 적으면 '입금 완료'로 표시합니다(고정환율 추산액과의 차이는 환율 차이로 보고 부분 입금으로 보지 않음). 입력 양식의 **비고** 칸은 기본 화면에 있습니다.
- **선택 삭제(관리자·작성자):** 사업 원장 행 앞 체크박스로 고른 뒤 [선택 삭제] → "삭제할까요?" 확인 창에서 [확인]을 눌러야 삭제됩니다(실적 반영 ON 건이 섞여 있으면 함께 경고). 삭제한 건은 변경 이력에서 [복원]할 수 있습니다.
- **관리자 알림 [확인]:** 대시보드 맨 위 '관리자 확인 필요'(중복 의심·BIS 매출현황 누락)는 건별 [확인] 또는 [모두 확인]을 누르면 사라지고 변경 이력에 남습니다(관리자 모드 필요). '실적 반영 대기' 안내는 [확인]으로 닫히며 대기 건이 바뀌면 다시 보입니다.
- **사업명(상세내용):** 입력 양식 첫 묶음('어떤 사업인가요?')에서 바로 입력·수정합니다(필수 아님).
- **이번 주 신규:** 이번 주(월요일부터)에 처음 등록된 사업(화면 입력·엑셀·BIS 업로드)은 사업 원장 브랜드 앞에 **「신규」** 스티커가 붙고, 요약의 **[이번 주 신규 N건]**을 누르면 신규만 봅니다. 대시보드 **'이번 주 신규 사업'** 섹션(기본: KPI 바로 아래, 관리자 설정 → 섹션 구성에서 순서·표시 변경)에 건수·금액·목록이 나옵니다. 예전 건의 등록일은 변경 이력의 '추가' 기록으로 채웠고, 시트에서 옮겨 온 건은 신규로 보지 않습니다.
- **다음 할 일(목록에서 선택):** 보고 진행 현황·이번 주 신규 사업 표의 '다음 할 일' 칸에서 바로 고르면 즉시 저장됩니다(입력 양식의 '진행 단계' 묶음에서도 선택). 진행 단계와는 연동하지 않으며, 목록은 기준 정보 → 선택 목록 → '다음 할 일'에서 관리합니다(처음 값은 기본 진행 단계 이름). 자동 안내(금액 입력 필요 등)는 그 아래 작은 칩으로 함께 보입니다.
- **진행 단계 편집(관리자):** 관리자 모드 → [관리자 설정] → ④ 진행 단계에서 단계 추가·이름 변경·순서(▲▼)·구분(진행 중/확정/종료)·설명을 바꾸고 [진행 단계 저장]. 이름을 바꾸면 그 단계였던 사업도 함께 바뀌고(변경 이력 기록), 사용 중인 단계는 지울 수 없습니다. 관리자 설정의 일반 [저장]·되돌리기·기본값 복원은 진행 단계·선택 목록을 바꾸지 않습니다.
- **같은 사업 자동 인식:** 업로드할 때 이름 표기가 조금 달라도(ZUS Coffee ↔ ZUS커피, CK ↔ 캘빈클라인, 포켓몬GO ↔ 포켓몬고, 계약구분 광고 ↔ 기타) 같은 그룹 안에서 브랜드·금액·시작 월·사업명 단어로 같은 사업을 찾아 한 건으로 유지합니다. BIS는 보고 단계를 모르므로, 확정↔확정·진행 중↔진행 중이면 플랫폼의 단계(예: 계약 체결 완료, 총괄님 승인 완료)를 유지하고 실적 반영도 끄지 않습니다.
- **관리자 알림:** 확실하지 않은 건은 새로 넣되 '중복 의심'으로 표시합니다(BIS 안의 완전히 같은 행, 금액·시기가 겹치는 기존 사업 등). 관리자 모드이거나 팀원 명단 역할이 '관리자'인 사람이 접속하면 대시보드 맨 위에 '관리자 확인 필요 N건' 알림과 사업 원장 탭 배지가 뜹니다. [확인하러 가기] → 해당 건을 열어 중복이 아니면 [확인 완료(중복 아님)], 중복이면 [삭제].
- **IP팀:** 사업 원장 [＋ 새로 추가]로 직접 입력합니다. MG(선급 보장금)와 로열티 초과분은 인정 시점이 달라 행을 나눠 입력합니다.
- **동시 접속(12명 기준):** 대시보드 읽기 요청을 한 번의 서버 실행으로 묶어 접속당 서버 실행이 약 3건입니다(Apps Script 동시 실행 한도 계정당 30건). 접속이 몰려 일시적으로 거절되면 화면이 1→2→4초 간격으로 자동 재시도하며 '접속이 몰려 다시 시도 중…'으로 표시합니다. 다른 분이 업로드·가져오기 같은 큰 작업 중이면 저장이 최대 30초 기다렸다가, 그래도 안 되면 '잠시 후 다시' 안내가 뜨고 입력 내용은 창에 그대로 남습니다. 다른 분의 변경은 최대 1분 뒤 반영되며, 화면 오른쪽 위에 '최근 갱신' 시각이 표시됩니다.
- **엑셀 업로드 진행 표시:** ① 읽기 ② 서버 확인 ③ 미리보기 ④ 반영 단계와 경과 시간이 표시됩니다. 오류 행은 미리보기 맨 위에 행 번호·이유로 모아 보여 주고, 나머지는 [반영하기]로 저장됩니다. 엑셀 도구를 외부 서버(cdnjs → jsDelivr → unpkg)에서 불러오는데, 모두 막히면 원인을 안내합니다.
- **동시 편집:** 두 사람이 같은 항목을 동시에 고치면, 나중에 저장하는 사람에게 "먼저 수정됨" 안내가 나와 덮어쓰기를 막습니다.

## 6. 기존 저장 기록 옮겨 오기 (선택, 약 3분)

기존 대시보드에서 저장해 둔 화면 선택(사업 일정 조정 등)을 새 대시보드에서도 쓰려면, 기존 프로젝트의 스크립트 속성 값을 복사해 옵니다.

1. 기존 프로젝트 **광고IP사업** → ⚙ 프로젝트 설정 → 스크립트 속성에서 아래 속성이 있으면 **값을 복사**합니다.
2. 새 프로젝트의 스크립트 속성에 **같은 이름으로 추가**합니다.

| 속성 이름 | 내용 |
|---|---|
| `BIZ_EVENT_OVERRIDES_JSON` | 사업 일정 직접 추가·제외 |
| `INSIGHT_OVERRIDES_JSON` | 인사이트 확정·수정 문구 |
| `UPCOMING_INSIGHT_SELECTION_JSON` | "차주엔~" 배지 직접 선택 |

- 속성이 없으면 저장한 적이 없는 것이니 건너뛰면 됩니다.
- **병행 기간에는 편집을 한쪽 화면(새 대시보드 권장)에서만** 해 주세요. 양쪽에서 따로 편집하면 두 화면의 선택이 서로 달라집니다.

## 7. 관리자 설정(관리자 모드 → [관리자 설정] 탭)에서 바꿀 수 있는 항목

예전 별도 주소(`?page=admin`)는 새 위치 안내만 보여줍니다. 모든 칸 옆 **?** 에 마우스를 올리면(휴대폰은 누르면) 무엇을 넣는지·예시·바꾸면 어디에 영향이 가는지가 나옵니다. 맨 위 **설정 점검표**에서 ⚠ 항목을 누르면 해당 칸으로 이동합니다.

| 구분 | 항목 |
|---|---|
| ① 기본 정보 | 대시보드 제목, 팀명(국문·영문) (운영 연도는 기준 정보 탭) |
| ② 데이터 연결 | BIS 업로드 폴더, 팀 구글 캘린더·표시 이름, [연결 테스트](협업 DB·BIS 폴더·주간 자동 기록·팀 캘린더) · 고급: 협업 DB 시트 |
| ③ 대시보드 화면 | 섹션 순서(▲▼)·표시·이름, 계약 종료 알림 시점, 사업 일정 키워드·표시 기호, '차주엔~' 배지 키워드·기간 |
| ④ 보안 | 대시보드·관리자 비밀번호 변경 |
| ⑤ 변경 이력 | 저장할 때마다 변경자·메모와 함께 기록(최근 20건), [되돌리기], [기본값으로 복원] |

처음 설치하면 **현재 운영값(2026)이 기본값으로 들어 있어** 바로 쓸 수 있습니다. 저장하면 즉시 반영되고, 대시보드를 새로고침하면 바뀐 내용이 보입니다.

## 9. 2027 전환 절차 (코드 수정 없음, 플랫폼 관리자 모드)

1. 플랫폼에서 **관리자 모드**를 켭니다.
2. **기준 정보** 탭 → 운영 연도 `2027` → **[운영 연도 전환]**. 모든 팀원의 기본 화면이 2027년으로 바뀝니다. 2026년 데이터는 오른쪽 위 연도 선택으로 계속 조회할 수 있습니다.
3. **KPI 목표·환율** 탭에서 2027년 KPI 목표(전체·광고·IP × 연간·상·하반기)와 2027년 KPI 고정환율을 입력합니다.
4. 사업 원장에서 2027년 사업은 'KPI 기준연도'를 2027로 입력하고, 확정되면 관리자가 실적 반영합니다.
5. 팀원에게 새 대시보드 주소만 쓰도록 공지합니다. GitHub Pages와 기존 프로젝트("광고IP사업")는 운영을 종료하고 보관합니다(삭제는 별도로 결정).

## 10. 참고·주의

- 관리자 설정은 관리자 모드를 켜야만 탭이 보입니다(관리자 비밀번호 필요).
- 대시보드 화면에는 시트·캘린더 ID가 내려가지 않습니다. 표시용 설정(제목, 키워드, 섹션 구성)만 전달됩니다.
- 관리자 설정의 저장값은 스크립트 속성 `PLATFORM_CONFIG_JSON`에, 변경 이력은 `PLATFORM_CONFIG_HISTORY`와 `PLATFORM_CONFIG_HIST_*`에 보관됩니다. **직접 지우지 마세요.**
- 설정을 바꾼 뒤 최대 60초 동안 이전 데이터가 보일 수 있습니다. 저장할 때 캐시를 비우지만, 다른 팀원 화면은 새로고침해야 반영됩니다.
- 코드를 다시 수정해야 할 때는 Claude나 제미나이 등 어떤 도구를 쓰든, 이 폴더의 파일 3개와 이 안내서를 함께 전달하면 같은 방식으로 이어서 작업할 수 있습니다.
