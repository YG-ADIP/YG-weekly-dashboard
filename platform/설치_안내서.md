# 주간회의 대시보드 플랫폼 — 설치·운영 안내서

> 대상: 엘라(관리자) · 작성: 2026-11 · 설치 방식: **새 Apps Script 프로젝트** · 소요 시간 약 20분

## 1. 무엇이 바뀌나

| 구분 | 기존 | 플랫폼 |
|---|---|---|
| 화면 제공 | GitHub Pages (`docs/index.html`) | **새 Apps Script 웹 앱이 직접 제공** (GitHub 불필요) |
| 고정값 관리 | 코드에 직접 기입 → 수정 시 코드 변경·배포 | **관리자 설정 화면에서 입력·저장** (코드 수정·재배포 불필요) |
| 접근 | 공통 비밀번호 | 공통 비밀번호(대시보드) + **관리자 비밀번호(설정 화면)** |

- **기존 프로젝트("광고IP사업")와 기존 GitHub 화면은 전혀 건드리지 않습니다.** 새 프로젝트를 따로 만들어 병행 운영합니다.
- 두 대시보드는 **같은 시트·캘린더를 읽기** 때문에 숫자와 일정은 똑같이 나옵니다.
- 다만 **화면에서 저장하는 기록은 프로젝트마다 따로 보관**됩니다. 사업 일정 직접 추가·제외, 인사이트 확정, "차주엔~" 배지 선택이 여기에 해당합니다. 설치할 때 한 번 옮겨 오는 방법은 4장을 참고하세요.

| 화면 | 주소 |
|---|---|
| 새 대시보드 | 새 프로젝트의 웹 앱 주소 (`https://script.google.com/macros/s/…/exec`) |
| 새 관리자 설정 | 새 웹 앱 주소 뒤에 `?page=admin` |
| 기존 대시보드 | 지금 쓰는 GitHub Pages 링크 (변경 없음) |

## 2. 준비물 (이 폴더의 파일 3개)

| 파일 | 새 프로젝트에 넣을 이름 | 내용 |
|---|---|---|
| `Code.gs` | `Code.gs` (기본 파일 내용 교체) | 데이터·설정·화면 제공 백엔드 |
| `Index.html` | **`Index`** (HTML 파일 추가) | 대시보드 화면 |
| `Admin.html` | **`Admin`** (HTML 파일 추가) | 관리자 설정 화면 |

파일 이름은 대소문자까지 정확히 `Index`, `Admin`으로 맞춰야 합니다. 확장자 `.html`은 Apps Script가 자동으로 붙입니다.

## 3. 설치 절차

1. **새 프로젝트 만들기:** script.google.com → **새 프로젝트** → 왼쪽 위 '제목 없는 프로젝트'를 눌러 이름을 정합니다(예: `주간회의 대시보드 플랫폼`).
   - 기존 시트와 캘린더를 읽어야 하므로 **기존과 같은 구글 계정(엘라 계정)**에서 만들어야 합니다.
2. **Code.gs:** 기본으로 들어 있는 `function myFunction() {}`을 모두 지우고, 이 폴더의 `Code.gs` 내용 전체를 붙여 넣은 뒤 저장(`Ctrl+S`)합니다.
3. **HTML 파일 2개 추가:**
   1. 왼쪽 파일 목록의 **＋ → HTML**을 누르고 이름을 `Index`로 입력합니다.
   2. 기본 내용을 지우고 `Index.html` 내용을 붙여 넣은 뒤 저장합니다.
   3. 같은 방법으로 `Admin` 파일을 만들고 `Admin.html` 내용을 붙여 넣은 뒤 저장합니다.
4. **비밀번호 2개 등록:** 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **속성 추가**에서 아래 2개를 넣고 저장합니다.

   | 속성 | 값 |
   |---|---|
   | `DASHBOARD_PASSWORD` | 팀 공통 비밀번호 (기존과 같게 하면 팀원 안내가 쉬움) |
   | `ADMIN_PASSWORD` | 관리자 비밀번호 (공통 비밀번호와 다르게) |

5. **권한 승인 (처음 1회):**
   1. 편집기 위쪽 함수 선택 드롭다운에서 `manualAuthTest`를 고르고 **▶ 실행**을 누릅니다.
   2. "권한 검토" 창이 뜨면 본인 계정 → **고급** → **(프로젝트명)(으)로 이동** → **허용**을 누릅니다.
   3. 이 단계를 건너뛰면 시트·캘린더 데이터가 비어 보일 수 있습니다.
6. **배포:** 오른쪽 위 **배포 → 새 배포**를 누릅니다. 새 프로젝트라서 이번에는 "새 배포"가 맞습니다.
   - 유형(⚙): **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 후 나오는 **웹 앱 주소(…/exec)**가 새 대시보드 주소입니다. 복사해서 보관하세요.
7. **확인:**
   1. 새 주소로 입장해 기존 화면과 같은 내용이 나오는지 봅니다.
   2. 주소 뒤에 `?page=admin`을 붙여 관리자 비밀번호로 입장한 뒤 **[연결 테스트]**를 눌러 6개 항목이 모두 ✅인지 확인합니다.
8. **이후 코드를 수정할 때:** **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**로 올립니다. 이렇게 하면 주소가 유지됩니다. 문제가 생기면 같은 화면에서 이전 버전 번호를 골라 다시 배포합니다.

## 4. 기존 저장 기록 옮겨 오기 (선택, 약 3분)

기존 대시보드에서 저장해 둔 선택을 새 대시보드에서도 그대로 쓰려면, 기존 프로젝트의 스크립트 속성 값을 복사해 옵니다.

1. 기존 프로젝트 **광고IP사업** → ⚙ 프로젝트 설정 → 스크립트 속성에서 아래 속성이 있으면 **값을 복사**합니다.
2. 새 프로젝트의 스크립트 속성에 **같은 이름으로 추가**합니다.

| 속성 이름 | 내용 |
|---|---|
| `BIZ_EVENT_OVERRIDES_JSON` | 사업 일정 직접 추가·제외 |
| `INSIGHT_OVERRIDES_JSON` | 인사이트 확정·수정 문구 |
| `UPCOMING_INSIGHT_SELECTION_JSON` | "차주엔~" 배지 직접 선택 |

- 속성이 없으면 저장한 적이 없는 것이니 건너뛰면 됩니다.
- **병행 기간에는 편집을 한쪽 화면(새 대시보드 권장)에서만** 해 주세요. 양쪽에서 따로 편집하면 두 화면의 선택이 서로 달라집니다.

## 5. 관리자 설정 화면에서 바꿀 수 있는 항목

| 구분 | 항목 |
|---|---|
| 1. 기본 정보 | 대시보드 제목, 팀명(국문·영문), **기준 연도** (섹션 이름의 `{year}`에 자동 반영) |
| 2. 데이터 연결 | 실적현황 시트, 팀 AGENDA 폴더, 트렌드 리포트 폴더, 사업 캘린더 시트, 팀 구글 캘린더, 캘린더 표시 이름, KPI 원본 시트 링크 · **주소(URL)를 붙여 넣으면 ID 자동 추출** |
| 3. KPI 예비 목표 | 시트에 목표가 비었을 때만 쓰는 연간·하반기 목표 |
| 4. 사업 캘린더 | 계약 알림 시점(N개월 전, 최대 4개), 사업 일정 표시 기호(◈), 사업 일정 키워드 |
| 5. 팀 일정 | "차주엔~" 배지 키워드, 미리보기 기간(일) |
| 6. 섹션 구성 | 섹션 순서(▲▼), 표시·숨김, 섹션 이름 · 번호는 자동으로 다시 매겨짐 |
| 7. 연결 테스트 | 저장 전에 각 시트·캘린더를 실제로 열어 필요한 표가 있는지 ✅/❌로 확인 |
| 8. 보안 | 대시보드·관리자 비밀번호 변경 |
| 9. 변경 이력 | 저장할 때마다 변경자·메모와 함께 기록(최근 20건), [되돌리기], [기본값으로 복원] |

처음 설치하면 **현재 운영값(2026)이 기본값으로 들어 있어** 바로 쓸 수 있습니다. 저장하면 즉시 반영되고, 대시보드를 새로고침하면 바뀐 내용이 보입니다.

## 6. 3주 병행 운영 점검표

| 점검 항목 | 기존 화면 | 새 화면 |
|---|---|---|
| KPI·상하반기 수치가 같은가 | ☐ | ☐ |
| 월별 트래킹·팀 AGENDA·트렌드 리포트 내용이 같은가 | ☐ | ☐ |
| 사업 캘린더 계약 카드·사업 일정 카드가 같은가 | ☐ | ☐ |
| 사업 일정 [편집] → [저장]이 동작하는가 (새 화면) | — | ☐ |
| 인사이트 확정, 섹션 접기, 트렌드 펼쳐 보기가 동작하는가 | ☐ | ☐ |
| 관리자 설정 저장·되돌리기가 동작하는가 (새 화면) | — | ☐ |
| 첫 화면 로딩 속도가 괜찮은가 | ☐ | ☐ |
| 팀원 접속에 문제는 없는가 (링크·비밀번호) | ☐ | ☐ |

## 7. 2027 전환 절차 (코드 수정 없음)

1. 2027 시트들을 준비합니다(실적현황_2027 등). 표 머리글 형식은 2026과 같게 맞춥니다.
2. 새 관리자 설정에서 아래를 입력합니다.
   1. **1. 기본 정보:** 기준 연도를 `2027`로 바꿉니다.
   2. **2. 데이터 연결:** 새 시트·폴더 주소를 붙여 넣습니다.
   3. **3. KPI 예비 목표:** 2027 목표를 입력합니다.
3. **[연결 테스트]**로 모두 ✅인지 확인하고, 메모 "2027 전환"을 적어 **[저장]**합니다.
4. 팀원에게 새 대시보드 주소를 공지합니다. GitHub Pages와 기존 프로젝트("광고IP사업")는 운영을 종료하고 보관합니다(삭제는 별도로 결정).
5. 이상이 있으면 **9. 변경 이력**에서 직전 설정으로 [되돌리기]합니다.

## 8. 참고·주의

- 대시보드 화면에는 시트·캘린더 ID가 내려가지 않습니다. 표시용 설정(제목, 키워드, 섹션 구성)만 전달됩니다.
- 관리자 설정의 저장값은 스크립트 속성 `PLATFORM_CONFIG_JSON`에, 변경 이력은 `PLATFORM_CONFIG_HISTORY`와 `PLATFORM_CONFIG_HIST_*`에 보관됩니다. **직접 지우지 마세요.**
- 설정을 바꾼 뒤 최대 60초 동안 이전 데이터가 보일 수 있습니다. 저장할 때 캐시를 비우지만, 다른 팀원 화면은 새로고침해야 반영됩니다.
- 코드를 다시 수정해야 할 때는 Claude나 제미나이 등 어떤 도구를 쓰든, 이 폴더의 파일 3개와 이 안내서를 함께 전달하면 같은 방식으로 이어서 작업할 수 있습니다.
